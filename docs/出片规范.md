## MV 工作台 (界面 「视频生成 → MV 工作台」)

一 个 首尾帧 片段 只 有 几 秒, 单看 没 用 —— 它 的 用处 是 "一 串 关键帧 之间 的 过 场".
所 以 界面 里 **只 留 首尾相接** 这一 种 玩法 (原来 的 两两配对 / 只做首帧 已 删).

    关键帧:  图1 -> 图2 -> 图3
    镜头 1:  图1 当 首帧, 图2 当 尾帧
    镜头 2:  图2 当 首帧, 图3 当 尾帧
    MV:      镜头1 + 镜头2 (+ 配乐)

### 分 工 (用户 定 的)
| 谁 | 干 啥 |
|---|---|
| **远端机** | 只 出 镜头 (机器 大, 权重 全, 出片 快) |
| **本机** | 做 合并 —— 拼接 (concat) + 配乐 (mux) **一律 在 本机** |

- 镜头 在 远端机 出 的 时 候, 本机 通过 SSH 把 批次 交 过去, 出 完 把 mp4 **scp 回 本机**, 再 在 本机 拼.
- 反过来 (远端机 拼完 再 传 回 本机) 是 白 传 一 轮 —— 不 这么 做.
- 配乐 是 本机 出歌 产物, 直接 引用 本机 文件, 零 传输.
- 成品 MV 落 在 `~/Documents/MLX Studio 输出/视频/MV<月日时分>/`.

### 端点
| 端点 | 干 啥 |
|---|---|
| `POST /v1/video/mv` | 提交 (frames / prompts / node / music / 参数) |
| `GET  /v1/video/mv?id=` | 进度 (log / done / total / shots / mv) |
| `GET  /v1/audio/files` | 本机 出歌 产物 (配乐 下拉) |
| `GET  /v1/video/nodes` | 可 用 节点 (本机 / 远端机, 带 连通 性) |

### 注意
- 跑 完 **不 立刻 卸 模型** —— 只 关 会话, 引擎 留 着, 置闲 30min 后 自动 卸 (下 一 批 不用 重 载 25G).
- 镜头 建议 3~6 个 —— 每个 ~2~7min, 太多 要 跑 很 久.

## 定 死 参 数
- 量 化: 4bit DiT (25G, adaln 8bit) — 画 质 可 接 受
- 步 数: 8-step (画 质 档; 4-step 偏 糊 不 用)
- 画 幅: 768 短 边 (H3 训 练 画 幅), 横 屏 1344x768
- 时 长: 5s/片 (124 帧), 每 片 ~8min (2026-11-25 实测: 124 帧 ≈ 8 分钟)
- 内 存 峰 值: ~74G (96G 装 得 下, 不 换 页)

## 4 分 钟 MV (48 片 5s)
1. GET /session?kind=video  -> 拿 sid (加 载 一 次 DiT)
2. for i in 1..48:
     GET /video?session=$sid&prompt=<分 镜 i>&sec=5&steps=8&seed=<i>
   (会 话 内 热 出, 不 重 载 不 卸, 每 片 ~7min)
3. GET /session/close?sid=$sid  (卸 模 型)
- 总 时 长: ~48 x 8min = 6~7h (2026-11-25 实测 换算, 挂 一 晚 出 完)
- 会 话 30min 无 新 片 自 动 卸 (防 忘 关)

## 内 存 守 门
- 可 用 <15G 时 /video 拒 绝 (503), 防 顶 爆 崩 机
- 出 完 片 立 即 卸 DiT (非 会 话); 会 话 内 常 驻

## 画 质 升 级 选 项 (现 在 不 必 要)
- 6bit DiT: 画 质 更 稳, 内 存 峰 值 ~79G (96G 装 得 下), 需 先 量 化
- 8bit DiT: 近 无 损, 内 存 峰 值 ~84G (顶 紧), 不 推 荐 96G 机 常 用
