# MLX Studio 标准工作流（远端机 出片 · 本机主控）

> 适用范围：H3 出片、MV 成片。命令可直接复制。
> 版本 2026-11-25 —— 全部数字来自当天在 出片节点（<出片节点IP> / 96G）上的实跑，不是推测。

---

## 0. 一分钟看懂

| 机器 | 角色 | 干什么 | 不干什么 |
|---|---|---|---|
| **出片节点**（<出片节点IP> / 96G / 出片机） | 出片节点 | 跑 H3 DiT，出镜头 mp4 | **不做** concat / mux / 配乐 |
| **主控机**（128G / 主控） | 主控调度 | 出歌、专辑图、**拼接 concat + 贴歌 mux**、拉回产物 | 不跟 远端机 抢出片 |

**铁律**：镜头在 远端机 出 → scp 回本机 → 在本机拼。反过来（远端机 拼完再传回）是白传一轮。

## 1. 环境自检（每次开工前 30 秒）

### 鉴权规则（**最容易踩的一条**）

远端内核带 `--api-key`：

| 从哪访问 | 要不要 key |
|---|---|
| `http://127.0.0.1:11251`（就在 远端机 上跑） | **不要**（loopback 免鉴权） |
| `http://<出片节点IP>:11251`（本机 / 局域网任意机器 / 远端机 用自己的 LAN IP） | **必须**带 `Authorization: Bearer <key>`，否则 **401**（连 `/health` 都 401） |
| `http://<出片节点IP>:11251/out/...`（取产物） | 免鉴权 |

key 在 远端机 的 `~/Library/LaunchAgents/com.ours.mlxstudio.plist` 里（`--api-key` 参数）。

> **key 是每台机器自己的**（launchd plist 里的 `--api-key`），
> 换机器要自己生成一份，**不要**写进任何会进仓库的文件。
> 上面那行直接从 launchd 里读，不用手抄。

```bash
# ① 远端内核在不在
ssh -o BatchMode=yes <user>@<出片节点IP> 'launchctl list | grep mlxstudio'
#    期望：一行 "12345  0  com.ours.mlxstudio"（第二列 0 = 没崩过）

# ② 接口 + 路由 + 空闲内存（注意要带 key）
export KEY="$(launchctl print gui/$(id -u)/com.ours.mlxstudio | awk '/--api-key/{print $NF}')"
curl -s -H "Authorization: Bearer $KEY" http://<出片节点IP>:11251/health
#    期望：{"status":"ok","loaded":[],"route":{"video":"remote","image":"remote","music":"local"},"free_gib":85+}
#    loaded 非空 = 上次的 DiT 还常驻（省 25G 重载，正常）

# ③ 本机能不能连 远端机
curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $KEY" \
  http://<出片节点IP>:11251/v1/models                                           # 期望 200

# ④ 本机 ffmpeg（concat / mux 全靠它）
which ffmpeg || ls /opt/homebrew/bin/ffmpeg
```

远端机 上没有 ffmpeg 是正常的（没 Homebrew）：内核用 `~/.ours/bin/ffmpeg` 兜底，服务 PATH 里已经带上它。

## 2. 定死参数（别改）

| 项 | 值 | 为什么 |
|---|---|---|
| 量化 | 4bit DiT（25G，adaln 8bit） | 画质可接受，96G 内存峰值 ~74G |
| 步数 | **8 步** | 4 步偏糊；12 步时间翻倍、画质提升不明显 |
| 画幅 | **1344×768**（768 短边横屏） | H3 只在 768 短边发布，其他尺寸属离群 |
| 单镜头时长 | 5s = 124 帧 | 引擎硬上限 15s |
| 内存峰值 | ~74G | 96G 装得下，不换页 |

**可用内存 < 15G 时 `/video` 直接返回 503 拒绝**（防顶爆崩机）。看到 503 先看 `free_gib`，别盲目重试。

## 3. 路线 A：出一条连续长片（H3 链式窗口 = Continuum 语义）

**用途**：一条不切开的连续长片，窗口之间画面自动衔接。

### Step 1 · 开会话（让 25G DiT 常驻，别每片重载）

```bash
export 远端机=http://<出片节点IP>:11251
export KEY="$(launchctl print gui/$(id -u)/com.ours.mlxstudio | awk '/--api-key/{print $NF}')"
SID=$(curl -s -H "Authorization: Bearer $KEY" "$远端机/session?kind=video" \
  | python3 -c "import json,sys;print(json.load(sys.stdin)['session'])")
echo "sid=$SID"
```

### Step 2a · 出片（单提示词 → GET）

```bash
curl -s -G "$远端机/video" \
  -H "Authorization: Bearer $KEY" \
  --data-urlencode "session=$SID" \
  --data-urlencode "prompt=一个女孩走进夜色霓虹的街道，电影感镜头，浅景深" \
  --data-urlencode "sec=6" --data-urlencode "steps=8" --data-urlencode "seed=7" \
  --data-urlencode "width=1344" --data-urlencode "height=768" \
  --data-urlencode "chain_windows=2" | python3 -m json.tool
```

### Step 2b · 出片（每窗口不同提示词 → POST，`chain_prompts` 传数组）

```bash
curl -s -X POST "$远端机/v1/video/generations" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"第一个镜头","chain_prompts":["镜头1提示词","镜头2提示词","镜头3提示词"],
       "chain_windows":3,"sec":15,"steps":8,"seed":7,
       "width":1344,"height":768,"session":"'"$SID"'"}' | python3 -m json.tool
```

> GET 只能给**一条**提示词。多窗口分镜必须走 POST，body 里 `chain_prompts` 是数组。

### Step 3 · 拉回本机

```bash
scp "<user>@<出片节点IP>:~/Documents/MLX Studio 输出/视频/mx_video_XXXX.mp4" .
```

### Step 4 · 关会话（可选；30 分钟无新片会自动卸）

```bash
curl -s -H "Authorization: Bearer $KEY" "$远端机/session/close?sid=$SID"
```

### 参数真相表（踩过的坑全在这）

| 参数 | 真相 |
|---|---|
| `sec` | 是**总时长**，会被窗口平均分摊（`per = sec / chain_windows`）。要 3 窗口各 5 秒 → `sec=15`，**不是** `sec=5` |
| `chain_windows` | 1~6，超过 6 会被 clamp |
| `chain_prompts` | 每窗口一条（Continuum 的 Sequence Prompt 语义）。**少给时用最后一条兜底**；不给 = 一条提示词重复 N 遍，那不叫长片 |
| `first_frame_image` | **可以和 chain 同用** ✓：锚定**窗口 1** 的首帧，窗口 2 起自动接上一窗口末帧。语义正好 |
| `last_frame_image` | **chain_windows>1 时被静默丢弃**（代码里显式剔除，不报错）→ 别指望"锁尾帧" |
| `ref_images` | 可与 chain 同用，每个窗口都会带上参考图 |
| 窗口衔接 | **不用自己传图**：服务端自动把上一窗口的末帧作为下一窗口的首帧条件（实测窗口 2 带 1008 condition rows） |
| `seed` | 内部按窗口偏移 `seed + wi*1000`，各窗口自动不同，不用手动错开 |
| **帧数** | 接口报的 `frames` 是**模型帧数**，写出的 mp4 可能**少 1 帧**（音轨比视频长时 `save_mp4` 的 `-shortest` 会裁掉尾帧）。**以 `ffprobe nb_frames` 为准**，别拿接口值去排 concat 列表 |
| 产物 | 落 远端机 `~/Documents/MLX Studio 输出/视频/`，同源 `/out/<名字>` **免鉴权**可直接下载 |

### 实测基准（1344×768 / 8 步）

| 场景 | 帧数 | 耗时 |
|---|---|---|
| 1 窗口（3s） | 73 | ~2.8 分钟 |
| 1 窗口（5s） | 124 | ~8 分钟 |
| 2 窗口（各 3s） | 146 | **582 秒**（含模型加载） |
| 3 窗口（各 2s，POST + 3 条分镜提示词） | 168 | **653 秒**（含模型加载） |

**接缝质量**（2 窗口实测）：接缝帧差 **1.14**，窗口内平均 1.98 / 1.10 → 接缝比窗口内还平滑，肉眼看不出跳。

**3 窗口实测**（POST + `chain_prompts` 3 条）：接缝帧差 1.79 / 1.73，窗口内平均 0.94（最大 3.64）
→ 接缝略高于窗口内平均、但低于窗口内峰值，属自然衔接。
画面上 3 个窗口是**同一个人、同一件裙子、同一条霓虹街**，而每窗口分镜都生效了
（远景背影 → 正面中景 → 跟随近景）→ **连续性与分镜控制同时成立**。

> 小坑：接口报的 `frames`（168）比 mp4 实际帧数（167）多 1 —— 编码器取整，不用当 bug 追。

## 4. 路线 B：批量出 MV 成片（多镜头 + 配乐）

### 链路

```text
本机 launch_batch.py ──写参数──▶ 远端机 run_full.py ──▶ done.json（断点续跑）
                                                │
本机 watch_batch.sh ◀──盯结束────┘
      └─▶ pull_and_merge.py（scp 拉回 + 本机 ffmpeg concat）
```

### Step 1 · 备镜头脚本

每行一条 prompt，格式 `[序号] 提示词` 或裸提示词都行。文件放 远端机 的 `/tmp/`：

```bash
scp shots.txt <user>@<出片节点IP>:/tmp/mv_zh_shots.txt
```

> 素材是 PNG 分镜图时，prompt 藏在 PNG 的 `prompt` tEXt 里（ComfyUI 存的 workflow JSON，
> 取 `CLIPTextEncode` 节点的 `text`）。用 `sips -g all` 或 PIL 的 `pnginfo` 读。

### Step 2 · 起跑批（本机执行）

```bash
python3 <仓库>/launch_batch.py \
  '{"shots":"/tmp/mv_zh_shots.txt","sec":5,"steps":8,"resume":true}'
```

- `resume:true` → 读 远端机 的 `done.json`，已出的片跳过，中断后重跑接着来
- 远端机 侧跑批脚本 = `~/.ours/mlx_server/run_full.py`（**端口必须 11251**）

### Step 3 · 自动拉回 + 合并

`watch_batch.sh` 盯着 远端机 的 `run_full.py`，结束后自动跑 `pull_and_merge.py`（scp 回 + 本机 ffmpeg 拼）。

### 产物位置

| 阶段 | 位置 |
|---|---|
| 远端机 中间产物 | `~/Documents/MLX Studio 输出/视频/` |
| 本机合并产物 | `~/Desktop/rea/soak-results/mlxserve/mv_mp4/` |
| MV 成品 | `~/Documents/MLX Studio 输出/视频/MV<月日时分>/` |

## 6. 参考图模式（Continuum 的 reference）

参考图只进文本塔的视觉块，**不当关键帧条件**。提示词里用 `<Picture 1>` 指代（官方文案写 `@图片N`）。

只能走 POST（GET 的 URL 塞不下 base64）：

```bash
IMG=$(base64 -i /path/to/ref.jpg | tr -d '\n')
curl -s -X POST http://<出片节点IP>:11251/v1/video/generations \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -d "{\"prompt\":\"<Picture 1> 里的女孩转身走向镜头，霓虹街道，电影感\",
       \"ref_images\":[\"data:image/jpeg;base64,$IMG\"],
       \"sec\":5,\"steps\":8,\"seed\":11,\"width\":1344,\"height\":768}" | python3 -m json.tool
```

上限：图片 9 / 视频 3 / 音频 3（总计 12）。实测 1 张参考图 → 124 帧 / 472 秒，人物与影调跟着参考图走。

## 7. 故障排查（全部是当天真踩过的）

| 症状 | 原因 | 修 |
|---|---|---|
| 渲染到一半模型被抽走 | **不会发生**：`_video_busy` 在 `_do_video` 里、**在加载 25G 之前**就置位，evictor 见到 `_engine_in_use("video")` 为真只刷新计时不卸 | 真风险是**会话被关**：会话是另一个保护源，关掉会立刻卸引擎 → 下一片重载 25G（多花约 2 分钟，**不会失败**）。别关别人的 sid |
| mp4 帧数比接口报的少 1 | `save_mp4` 用 `-shortest` mux，音轨比视频长时裁掉视频尾帧（实测：接口 168 → mp4 167，音 6.975s vs 视 6.958s） | 用 `ffprobe nb_frames` 读实际帧数做拼接/对齐 |
| 局域网访问 远端机 全是 401 | 非 loopback 访问必须带 `Authorization: Bearer <key>`（**包括 远端机 用自己的 LAN IP 访问自己**） | 所有 curl 加 `-H "Authorization: Bearer $KEY"`；只有 `127.0.0.1` 和 `/out/` 免鉴权 |
| 第 2 个窗口崩：`'QuantizedLinear' object has no attribute 'weight'` | 上游默认 `drop_adaln=True`，第一次出片就把 AdaLN 权重删了，第二个窗口重建调度表时炸 | `engine.py` 传 `drop_adaln=False`（代价：多占 ~6.5G 显存，96G/128G 都宽裕） |
| 传参考图直接 `TypeError` | 运行时 import 的是厂商源码包，不是我们的补丁层 → 补丁是死代码 | `install.sh` 的 `overlay_h3_patch()` 把补丁层覆盖到 vendor 源码上；装完必须看到 `[install] ✓ H3 补丁 覆盖 上` |
| 补丁层明明在，overlay 却没生效 | overlay 找 `源码目录/port_minimax_h3_mlx`（里面），实际补丁层是**同级** → 永远静默跳过 | overlay 同级和里面都找；找不到就打印警告，不静默 |
| 抽帧/预览静默失败（返回空） | 远端机 没 Homebrew，服务 PATH 里没有 ffmpeg | `env.sh` 和 `install.sh` 都加 `$HOME/.ours/bin` 进 PATH |
| 跑批一片都出不来（Connection refused） | 脚本端口写死 11250，远端机 现在跑 11251 | 改成 11251（可用 `MLX_BASE` 覆盖） |
| 重装后批跑脚本不见了 | `install.sh` 文件清单里没有跑批脚本 | 补进清单（run_full.py / run_batch.py / batch_mv.sh / finish_batch.sh） |
| `run_local_dev.sh` 在 远端机 上静默指空 | 写死本机 `~/Desktop/rea/ours/_vendor` | 改成「存在就用」，自动挑 vendor / 权重 / venv / ffmpeg |

### 排他 vs 内存红线（两条不同的问题，别混）

| 现象 | 含义 |
|---|---|
| **409** `已 有 出 片 在 跑` | 出片排他：一次只出一片。在 远端机 上起第二个出片进程就是 409，排队即可 |
| **503** `可 用 XG < 15G, 拒 绝 起 视 频` | 内存红线，判在**出片那台机**（远端机）上。本机跑重型任务**不会**推高 远端机 的 `free_gib`（远端机 当前约 20G） |
| 渲染中途被卸模型 | **不会**——`_video_busy` 在加载模型前就置位，evictor 会跳过 |
