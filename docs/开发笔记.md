# 我们自己的 mlx_server —— 闭源 MLX-Serve 的自研替代品

目标：彻底**不依赖**闭源 `mlx-serve`（`/Applications/MLX-Serve.app`），用 Apple MLX 本体 +
开源 minimax-h3-mlx port + 自研稀疏注意力 Metal kernel，出 H3 视频 / Krea 图 / ACE-Step 歌 /
Qwen3 对话 / macOS-say 语音，并按逆向出来的**契约**把功能全部实现、界面全部复刻。

服务：`http://127.0.0.1:11251`（launchd `com.codex.mlxserver-dev` → `/tmp/mlx_server_run.sh`）
界面：`GET /` → **MLX Serve Studio** 控制台（11 页，中/EN 双语，主题可切）
出歌：顶层「**音乐**」页 = 独立 的 出歌工作台（MC 出歌工作台 已 整个 并进来）

## 出片 耗时（为什么 5 秒 要 那么 久）

H3 的 DiT 把 文本+音频+视频 latent 打包 成 **一条** 序列 一次 前向，注意力 是 **平方** 的：

```
rows = (画布宽/32) × (画布高/32) × latent帧数 + 音频行 + 文本行
latent帧数 = (帧数-5)/17*5 + 2            # 帧数 必须 17n+5
t_step ≈ 1.378e-4·rows + 1.409e-7·rows²   # 线性项=MLP, 平方项=注意力
```

所以 耗时 跟 「画布面积 × 帧数」 是 **平方级** 的 —— 机器 不慢，是 参数 大。

| 画布 | 帧数 | 步数 | rows | 耗时 |
|---|---|---|---|---|
| 704×448 | 124 | 4 | 11,847 | **97 秒**（实测） |
| 832×480 | 124 | 8 | 14,854 | 3.9 分钟（界面默认） |
| 1024×576 | 124 | 8 | 21,736 | 8.1 分钟 |
| 1344×768 | 124 | 8 | 37,720 | **24 分钟**（实测） |
| 1920×1088 | 124 | 4 | 75,904 | 41 分钟 |

**界面 出片 前 会 按 本机 实测 速度 显示「预计约 N 分钟」**，宽/高/帧数/步数 一改 就 重算。
内核 侧 每次 出片 都 记录 真实 的 行数 与 每步 耗时（`/props` 的 `last_video_*` / `video_fit_*`），
用 最近 8 次 实测 最小二乘 拟合 出 速度 曲线 —— 不 拍 脑袋。

## 两个 出片 引擎（不是一个）

| | MiniMax H3 | **Wan2.2 TI2V-5B** |
|---|---|---|
| 权重 | 25G（4bit DiT） | 20G（q8 DiT 5.4G + T5 11.4G + VAE 2.8G） |
| 帧数 规矩 | **17n+5** | **4n+1** |
| 首帧 | ✅ | ✅ |
| **尾帧** | ✅ | ❌（Wan 架构 没有 尾帧 条件） |
| 参考图 | ✅ | ❌ |
| 画布 | 自由 | 1280×704（720P，上限 901120 像素） |
| 声音 | 自带 音轨 | **静音**（音轨 由 本机 音乐 合成 后 mux） |
| 步数 | 4–50 | 固定 40（官方 40 步 / guide 5.0 / shift 5.0） |
| 快慢 | 慢（H3 是 33B） | **快 很多**（5B） |

两 个 是 **兄弟，不 是 替代**：要 完整 首尾帧 用 H3；要 快片 用 Wan2.2。
一次 只 装 一个（两个 DiT 加 起来 会 撞爆 内存），换 模型 自动 先 卸 旧 的。

**Wan2.2 权重 怎么来**（走 魔搭，跟 我们 其它 模型 一条 路）：

```bash
python tools/fetch_wan2_mlx.py --clean-src
```

从 魔搭 拉 `Wan-AI/Wan2.2-TI2V-5B-BF16`（Apache-2.0，24G 原始 权重），
用 上游 mlx-video 的 convert 脚本 在 本地 转成 MLX q8（~20G），顺带 拷 tokenizer
（装 完 离线 能 用，不 联网）。转 完 原始 权重 自动 删。

引擎 源码：`vendor_src/mlx_video/` = 上游 [Blaizzy/mlx-video](https://github.com/Blaizzy/mlx-video)
（MIT，**原样 vendor，一个字没改**）；我们 自己 的 包装 层 在 `port_wan2_mlx/`：

- **DiT 常驻** —— 上游 `generate_video()` 是 命令行 一次性 的（每次 重载 5.4G DiT），
  我们 是 桌面端 常驻 服务，批量 出片 时 一条 一条 生，所以 把 DiT 缓存 住。
- **T5 / VAE 临时** —— T5 被 上游 从 bf16 升成 float32（一次 就 22.7G），常驻 太 肥；
  出片 之间 装 一次、编完 文本 就 放。
- **截 帧** —— 上游 是 写 mp4，我们 直接 拿 帧 数组 回 我们 引擎 契约。
- **本地 tokenizer** —— 上游 硬 写 `"google/umt5-xxl"`（要联网），我们 从 权重 目录 读。

## 出歌 时长（自动 / 上限）

出歌 引擎 的 时长 是 **输入**（要 多少 秒 就 渲染 多少 秒），所以 界面 给 了 两 条 路：

- **自动**（`music_duration.py`）：按 歌词 本身 算 —— 认 段落 标记
  （`[intro]/[verse]/[chorus]/[bridge]/[outro]`、`Verse:`、中文「主歌/副歌」），
  每段 按 文字 量 算（中文 3.6 字/秒、英文 1.8 词/秒）+ 换气 + 过渡，向上 取整 到 5 秒。
  歌词 一 改，界面 实时 显示「自动 → 65 秒（7 段 · 10 行 · 122 字）」。
- **手动**：滑块 上限 = **引擎 真 上限**（`ACE_MAX_DURATION`，本机 480 秒 / 远端机 360 秒），
  超过 会 明说「超过 引擎 上限 N 秒, 已 按 上限」，**不 静默 截断**。

上限 **落 在 引擎 的 配方表 里**（`ace-step-engine/acestep_mlx/recipe.py` 的 `mini` preset = 480 秒），
所以 **任何 启动方式** 都 过 480 —— 不 靠 `--max-duration` 启动参数 兜底
（`--max-duration` 仍 可 覆盖，比 配方表 更 灵活）。

API 也 支持：`POST /v1/music/generate` 带 `duration_seconds:"auto"`；
`POST /v1/audio/music-generations`（OpenAI 兼容）同样 支持 `"auto"`，
clamp 用 的 是 引擎 真 上限（不 再 是 写死 的 600）；
`POST /v1/music/duration` 只 算 不 出。

## 已知限制（诚实说明）

- **出片很慢**：大画布 确实 慢（1344×768 / 8 步 = 24 分钟，实测）。
  界面 默认 已 改成 832×480 · 8 步（≈3.9 分钟），另 给 了 `preview` 4 步 档（≈2 分钟），
  并 显示 预计 耗时；视频引擎 **排他**（一次 只 出 一 片）。
- 本机**没有** LTX-2.5 / turbo LoRA / Kokoro / Qwen3-TTS 权重，且**无外网**（huggingface 不可达）。
  所以：LTX 专属字段与 `turbo` 一律 **400 指名**（闭源同款语义），不装样子。
- `ref_audio` 是 **PSOLA + 倒谱包络** 的真音色迁移（F1/F2/F3 落点误差 0 Hz），
  但**不是神经声纹克隆**（那要 Qwen3-TTS 权重）。
- 视频 `chain_windows` 长片 **已 端到端 跑通**（2026-11-24 实测）：832×480 / 8 步 /
  2 个窗口 × 3 秒 = **146 帧 + 立体声音轨**，端到端 385 秒。接缝（窗口1 末帧 → 窗口2 首帧）
  帧差 4.12，窗口内平均 1.65 —— 画面连贯（帧已逐帧核对）。
  之前那条「尚未端到端实跑」**已不成立**。
- **长片 跑通 的 关键 是 两个 bug**（都不是 模型 的 问题，是 我们 接线 的 问题）：
  1. **AdaLN 投影 不能 drop**：上游 默认 建好调制表后把 13B 的 `adaln_proj` 删掉省内存，
     但那是**一次性**操作，权重删了回不来。常驻服务里第二个窗口因为带了首帧条件、
     调度表变了要重建调制表 → 重建要调 `adaln_proj` → 权重没了 →
     `AttributeError: 'QuantizedLinear' object has no attribute 'weight'`。
     改法：`engine.py` 传 `drop_adaln=False`（4bit 下多占 ~6.5G，本机 128G / 远端机 96G 都宽裕）。
  2. **补丁层 之前 是 死代码**：`port_minimax_h3_mlx`（含 参考图 `ref_images` 和 远端机 上
     无 Homebrew 的 ffmpeg 兜底）从没被 import 过 —— 运行时加载的是上游原版。
     改法：`install.sh` / `build_app.sh` 在 vendor 源码装好后，把补丁层覆盖上去，并自检。
- 长片 每个 窗口 可以 有 **自己的 提示词**（ComfyUI Continuum 的 Sequence Prompt 语义）：
  API `chain_prompts`（数组），界面「分镜提示词」每行一个窗口；少给的用最后一条兜底。
  不给的话就是同一个提示词重复 N 遍——那不叫长片。
- macOS `say` 有些声音只 在英文下有声音（Reed/Rocko/Sandy 的 zh 变体读中文 = 静默）；
  本机真能读中文的只有 **Tingting / Meijia** —— TTS 会用探针自动换声并如实回报。
