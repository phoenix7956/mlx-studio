# 商用合规与授权申请清单

> 一句话：**MLX Studio 的代码随便商用；真正会卡住你的是权重。**
> 框架是 Apache-2.0（允许商用），引擎代码各有各的协议但都不禁止商用，
> 而**权重**里有两份社区许可带着**营收门槛**和**地域限制**——那才是要签字的地方。

本文按「你现在就要做什么」写，不是法务论文。条款数字全部来自仓库里
`vendor/` 下放着的协议原文（`MINIMAX-H3-COMMUNITY-LICENSE.txt`、
`vendor/krea2_engine_src/LICENSE`），随手可查。

---

## 一、三层许可，分开看

| 层 | 是什么 | 许可 | 商用 |
|---|---|---|---|
| **框架代码** | 我们自己写的内核、控制台、引擎适配、MCP | Apache-2.0 | ✅ 随便商用，不限营收、不限地区 |
| **引擎代码** | `vendor/` 下的 MLX 移植（MiniMax-H3 / Krea-2 / mlx-video / ACE-Step） | Apache-2.0 / Krea 2 Community / MIT | ✅ 不禁止商用（Krea 2 那份带条件，见下） |
| **模型权重** | 各家模型的参数文件 | 逐个不同 | ⚠️ **这里才有门槛** |

仓库**不携带任何权重**。用户点「下载」时，权重从上游自己的源（魔搭 / HuggingFace）拉，
用户点下载那一刻**自己**接受上游协议。我们不代签、不代接受、不做二次分发。

## 八、怎么自己查

**界面**：模型页 → 点「许可」列的徽章 → 看门槛 / 地域 / 署名 / 原文。

**API**：

```bash
curl -s http://127.0.0.1:11251/v1/licenses | jq '.data[] | {key,title,kind}'
curl -s http://127.0.0.1:11251/v1/licenses/minimax-h3 | jq -r .text | head -40
```

**深链**（直接打开某份许可）：

```
http://127.0.0.1:11251/?lic=minimax-h3
http://127.0.0.1:11251/?lic=krea-2
```

**文件**：

| 原文 | 路径 |
|---|---|
| 我们自己的许可 | `~/.ours/mlx_server/LICENSE` |
| 第三方声明 | `~/.ours/mlx_server/THIRD_PARTY_NOTICES.md` |
| H3 社区协议 | `~/.ours/mlx_server/vendor/minimax-h3_mlx_src/MINIMAX-H3-COMMUNITY-LICENSE.txt` |
| Krea 2 社区协议 | `~/.ours/mlx_server/vendor/krea2_engine_src/LICENSE` |

**代码里那份结构化条款**：`licenses.py`（模型 → 协议 key 的映射 + 门槛/地域/署名），
改条款只改这一个文件，界面、API、文档一起变。

## 九、别做的事

- ❌ **别为防云厂商托管就改 AGPL。** 会直接毁掉开源获客，
  而且跟上面这些门槛一点关系都没有 —— 门槛在权重协议里，不在框架许可里。
- ❌ **别做 dual MIT + proprietary。** 会让人困惑，
  而且 Apache-2.0 已经允许任何人商用，闭源化对你自己没好处。
- ❌ **别把权重打进安装包。** 仓库不带权重、装完自己下载，
  这样「用户自己接受上游协议」这条线就一直在，不用替用户担责。
- ❌ **别把「量化」当成换协议。** MLX 量化不改变上游权重的协议。
- ❌ **别删归属声明。** H3 §III.4、Krea §3.3 都明确禁止。
- ❌ **别在欧盟 / 英国 / 韩国 / 美国**用 H3 而不申请授权 —— 这跟营收无关。
