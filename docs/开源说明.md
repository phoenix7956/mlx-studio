# 开源说明 —— 仓库里有什么、没有什么、怎么配

> 一句话：**MLX Studio 是本机跑的开源 AI 创作工作台（框架）。**
> 仓库里是**代码**，不是**权重**，也不是**你的数据**。

这份文档回答四个问题：仓库边界在哪、密钥怎么配、第二台机怎么接、许可怎么算。

---

## 一、仓库包含什么

| 内容 | 路径 |
|---|---|
| 内核（HTTP 服务 + 能力引擎） | `server.py` / `api_full.py` / `cap_engines.py` / `engine.py` |
| 各能力实现 | `image_engine.py` / `music_engine.py` / `voice_studio.py` / `llm_engine.py` / `video_batch.py` |
| 界面（单文件前端） | `ui/console.html` |
| macOS 桌面 App 源码（Swift + AppKit + WKWebView） | `desktop/` |
| 第三方引擎源码（各自带 LICENSE / NOTICE） | `vendor/` / `vendor_src/` / `ace-step-engine/` |
| 一键安装 / 打包 | `install.sh` / `desktop/package.sh` |
| 回归测试（契约 38 条 + 能力 19 条） | `smoke_*.py` |

## 二、仓库**不**包含什么（重要）

| 不含 | 为什么 | 去哪拿 |
|---|---|---|
| **任何模型权重** | 单个权重几十 GB；且每个模型许可不同，不能替你打包 | 界面「模型」页下载，默认走**魔搭**，hf-mirror 兜底 |
| **任何 API key / 令牌 / 证书** | 密钥属于**使用者**，不属于项目 | 自己生成 —— 见第三节 |
| **任何机器地址、用户名、端口转发** | 开源版不写死任何人的部署 | 自己配 —— 见第四节 |
| **你的作品、资料库索引、输出文件** | 个人数据 | `~/Documents/MLX Studio 输出/`、`~/.ours/library.json` |
| **闭源 App 的代码 / 资源 / 二进制** | 本项目是 clean-room 实现，运行时也不读闭源 App 的任何文件 | 不需要 |
| **GPL / LGPL 的二进制**（如 ffmpeg） | 许可证不兼容，不能随仓库分发 | 装的时候从 pip 的 `imageio-ffmpeg` 取一份转发壳 |

> 第三方代码的授权明细见 [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md)。

## 三、密钥怎么配

### 内核的鉴权模型

内核启动参数有 `--api-key`。行为是：

- **不传 / 传空** → 不鉴权
- **传了** → **局域网里**的调用必须带 `Authorization: Bearer <key>`；
  **本机 loopback 调用免鉴权**（所以桌面 App 打开就是通的，不会满屏 401）

也就是说：**单机自用根本不需要 key**。

### 需要跨机调用时才配

自己生成一把，**别用网上抄的**：

```bash
python3 -c "import secrets,string;a=string.ascii_letters+string.digits;print('mlx_'+''.join(secrets.choice(a) for _ in range(32)))"
```

放进去的三个位置（**选一个就行**）：

**① launchd（推荐，macOS 常驻）**

```bash
# ~/Library/LaunchAgents/com.ours.mlxstudio.plist
#   EnvironmentVariables → MLX_API_KEY
#   或 ProgramArguments → --api-key <你的 key>
launchctl kickstart -k gui/$(id -u)/com.ours.mlxstudio
```

**② 环境变量**

```bash
MLX_API_KEY=<你的 key> launchctl setenv MLX_API_KEY <你的 key>
# 或 直接 起 内核 时:
~/.venvs/mlxstudio/bin/python server.py --port 11251 --api-key "$MLX_API_KEY"
```

**③ 桌面 App 界面**

App 内核菜单 → 设置 → 「API key」（给远端调用用；留空 = 不鉴权）。存在浏览器 localStorage。

### 用的时候怎么拿

```bash
export KEY="$(launchctl print gui/$(id -u)/com.ours.mlxstudio | awk '/--api-key/{print $NF}')"
curl -s -H "Authorization: Bearer $KEY" http://<另一台机器>:11251/health
```

### 换 key 的步骤

1. 改 plist / 环境变量里的值
2. `launchctl kickstart -k gui/$(id -u)/com.ours.mlxstudio` 重启
3. 另一台机器上同步改（它连你的时候要用你的 key）
4. 旧 key 立刻失效

### ⚠️ 一条硬规矩

**不要把 key 提交进任何公开仓库**，包括文档里的示例。

> 本项目自己踩过一次：早期版本的 `docs/标准工作流.md` 里把真实 key 写死成了示例，
> 仓库转公开后那段历史可被任何人翻到。发现后已经做了三件事 ——
> ① 两台机器全部换 key；② 文档改成从 launchd 里读，不再写死；
> ③ **用 `git filter-repo` 重写了整个 git 历史**，把 key / 内网地址 / 私人路径从
> 每一个历史 commit 里都抹掉后强制推送。
>
> 如果你 fork 了本仓库，**请重新 clone**，旧的历史里还有那段。

## 四、第二台机（出片 / 出图节点）怎么接

代码里**不写死任何机器**。`remote_node.py` 依次从三处读连接信息：

1. 环境变量 `REMOTE_SSH_TARGET` —— 完整 `user@host`
2. 环境变量 `REMOTE_SSH_HOST`（+ 可选 `REMOTE_SSH_USER`）
3. 本机配置文件 `~/.ours/node.json` —— `{"target": "user@host"}`（**这个文件不进仓库**）

```bash
# ~/.ours/node.json
{ "target": "youruser@192.168.x.x" }
```

读不到就返回空字符串 —— **本机独立跑时用不到第二台机**，功能不受影响。

出片 / 出图的路由由 `server.py` 的 `route` 决定（`{"video": "remote", "image": "remote", "music": "local"}` 这类），
在本机内核里改。

### 模型权重 —— 与本项目无关

**权重不随仓库分发。** 你下载哪个模型，就接受哪个模型作者的许可：

- Apache-2.0 / MIT 的（Wan2.2、Z-Image、MOSS-Image…）→ 自由，商用可以
- 社区许可的（MiniMax-H3、Krea-2…）→ 有附加条款（营收门槛 / 署名 / 地区限制），商用前自己看原文

**本项目不替你接受任何协议，也不替你承担商用判断。** 界面「模型」页每个权重都带许可徽章，
右上角「只看自由许可」可以把 ⚠ 的筛掉。

## 六、已知边界

- **只在 Apple Silicon 上跑**（Metal / MLX），没有 CUDA 路径。
- **内存**：H3 视频 / Krea 出图这类大模型吃统一内存，24G 起步、越大越快；模型闲置 30 分钟自动卸载。
- **不保证跨小版本兼容**：引擎升级后可能需要重下权重。
- 界面是中文 / English 双语，主题可切。

## 七、想复核仓库干不干净？

自己扫一遍（`git filter-repo` 之前的历史里曾经有以下内容，现在应该全部为空）：

```bash
# 当前 HEAD
git grep -nIE "(ghp_|gho_|github_pat_|mlx_[A-Za-z0-9]{20,}|Bearer [A-Za-z0-9_.-]{20,})"

# 整个历史
for c in $(git rev-list --all); do
  git grep -nIE "(ghp_|gho_|github_pat_|mlx_[A-Za-z0-9]{20,}|Bearer [A-Za-z0-9_.-]{20,})" $c --
done

# 私人路径 / 内网地址
git grep -nIE "/Users/[a-z]+|192\.168\." $(git rev-list --all) --
```

期望：全部无输出。
